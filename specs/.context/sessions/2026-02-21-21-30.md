## What did NOT go as planned

- First version of the web demo was cramped: nested `grid-cols-[1fr_auto]` sidebar layout didn't work. Had to rewrite to a clean vertical flow matching register/ALU pages.
- Dev server CSS caching issue: Tailwind styles weren't loading on the new `/memory` route until the `.next` cache was cleared and the dev server restarted. The page rendered completely unstyled (white background, no colors).
- Screen preview was initially non-interactive (view-only canvas). Added click-to-toggle-pixel after user feedback, which turned out to be the best teaching tool for memory-mapped I/O.

## New learnings captured

- [web-demo] Dev server `.next` cache must be cleared when adding new routes — CSS may not load otherwise
- [web-demo] Vertical flow with simple `lg:grid-cols-2` works better than complex nested grids for these demos
- [web-demo] Clickable canvas with crosshair cursor + address auto-jump is the best way to teach memory-mapped I/O
- [memory] Address decoding with bits [14:13] highlighted in amber on the bit grid is an effective visual teaching tool
- [web-demo] `Uint16Array` for memory state works well for React — copy with `new Uint16Array(state.arr)` for immutable updates

## New decisions captured

- ADR-001: Web demo pages use clickable canvas for screen memory (not individual DOM pixel elements) for performance
